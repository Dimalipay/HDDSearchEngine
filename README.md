# Lucene Desktop Search

## Конфигурация поиска и индексации

Все параметры собраны в `SearchConfig` и загружаются из `search.properties` (classpath).
При необходимости значения можно переопределять через `Preferences` API без пересборки.

Ключи конфигурации:

- `index.path` — путь к индексу.
- `lucene.version` — версия Lucene (для логирования).
- `index.ramBufferSizeMB` — размер RAM-буфера IndexWriter.
- `index.threads` — количество потоков индексации.
- `search.phraseSlop` — допуск фразового поиска.
- `search.defaultOperator` — `AND` или `OR`.
- `tika.maxStringLength` — максимальная длина извлекаемого текста.
- `tika.timeoutSeconds` — таймаут обработки одного файла.

## RussianAnalyzer: зафиксированное поведение

Проект использует **только** `RussianAnalyzer` для индексации, поиска и подсветки.
Поведение основано на `StandardTokenizer` и фиксируется тестами:

- пунктуация отбрасывается (включая символ `№`),
- числа сохраняются как отдельные токены,
- регистр нормализуется к нижнему,
- стоп-слова удаляются,
- морфологические формы приводятся к общему корню.

Практические последствия:

- запрос `№123` фактически ищет токен `123`;
- строка `договор № 45` токенизируется как `договор` и `45`;
- даты и идентификаторы, содержащие разделители (`12.03.2024`, `A-12`), разбиваются на отдельные токены.

Если требуется поиск по таким идентификаторам, используйте числовые или словесные части,
которые сохраняются анализатором.

## Защита от больших файлов

Apache Tika ограничивает длину извлекаемого текста (`tika.maxStringLength`) и
использует таймаут на обработку одного файла (`tika.timeoutSeconds`).
При усечении текста или превышении таймаута запись фиксируется в логах, а
индексация продолжается.

## Чтение .txt в разных кодировках

Для `.txt` файлов выполняется определение кодировки:

- сначала проверяется BOM (UTF-8/UTF-16LE/UTF-16BE),
- затем используется автоопределение через `juniversalchardet`,
- при неудаче применяется fallback на Windows-1251.

Чтение происходит через `InputStreamReader` с явно указанной `Charset`,
а выбранная кодировка и факт fallback логируются.


## Мультиязычный поиск (RU + EN)

Индексация и поиск выполняются одновременно для двух языков:

- `content_ru` и `filename_ru` анализируются `RussianAnalyzer`;
- `content_en` и `filename_en` анализируются `EnglishAnalyzer`;
- исходные поля `content`/`filename` сохраняются для обратной совместимости.

Для этого используется `PerFieldAnalyzerWrapper`, поэтому один документ индексируется сразу в RU и EN представлениях.
Поиск по полям `content` и `filename` выполняется через `MultiFieldQueryParser` по обоим языковым полям,
что позволяет находить русские, английские и смешанные запросы (например, `договор agreement`).


## Экспорт найденных документов

В интерфейсе доступна кнопка **«Экспорт найденных файлов»**.
Поддерживаются два режима:

- экспорт в папку;
- экспорт в ZIP-архив.

### Экспорт в папку

- выбирается целевая директория;
- сохраняется относительная структура каталогов файлов;
- при конфликте имени пользователь выбирает стратегию: **перезаписать / пропустить / переименовать**.

### Экспорт в ZIP

- пользователь выбирает путь и имя архива;
- используется стандартный `ZipOutputStream`;
- содержимое файлов не изменяется, структура каталогов внутри ZIP сохраняется.

При недоступных файлах ошибки логируются, экспорт остальных файлов продолжается.
Статус выполнения и прогресс отображаются в UI.


## Выбор диска/директории для индексации и объединённый поиск

В UI добавлены:

- выпадающий список логических дисков;
- кнопка **«Выбрать директорию»**;
- кнопки **«Проиндексировать выбранный диск»** и **«Переиндексировать»**.

Индексы хранятся раздельно в корневой папке индексов (`index.path`) с именами вида `index_<normalized>_<hash>`.
Это позволяет индексировать разные источники независимо и не перезаписывать ранее построенные индексы.

Метаданные индексов сохраняются в `indexes.json`:

- `path` (источник),
- `index_path`,
- `last_indexed`,
- `documents_count`,
- `index_size_bytes`,
- `status` (`READY` / `FAILED`).

Поиск выполняется сразу по всем готовым индексам через `MultiReader`,
поэтому пользователь получает объединённый результат из нескольких дисков/директорий.
